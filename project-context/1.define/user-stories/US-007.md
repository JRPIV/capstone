- **Priority**: Must
- **Persona**: Reviewer

### 2. Narrative

As a reviewer, I want a reconstructable record so I can verify the outcome.

### 3. Acceptance Criteria

1. Given stored tasks, messages, plan versions, and decisions, when the application restarts, then those records are preserved.
2. Given a repeated event ID, when it is processed, then no additional tasks, questions, or completions are created.
3. Given two hires, when one hire is updated, then the other hire’s plan does not change.
4. Given a failed interpretation, when it finishes, then the last verified facts remain intact and the failure is visibly reported.

### 4. Scope Notes

- **In Scope for MVP**: Local persistent storage; both seeded hires; sequential event processing; a documented reset and replay path; D11’s restart, replay, model-failure, and cross-hire checks.
- **Deferred**: Multiple concurrent operators, enterprise identity, and production integration recovery are out of this release.
