# User Story US-001: Create a supported plan

**PRD Document**: `project-context/1.define/prd.md` — Section 4, FR-01; BR-1; Appendix A; test D1  
**System Description**: `project-context/1.define/system-description.md` — FR-001, MD-001, MD-004, MD-005

### 1. Story Identity

- **ID**: US-001
- **Title**: Create a supported plan
- **Priority**: Must
- **Persona**: HR coordinator

### 2. Narrative

As an HR coordinator, I want an owned, dated plan so work can begin without manual task assembly.

### 3. Acceptance Criteria

1. Given a complete supported intake record, when that intake event is processed, then the plan contains exactly the four tasks in PRD Appendix A, with the owners and due dates in that table.
2. Given an incomplete record, when it is processed, then the missing fields are shown. Given a missing or unreadable input, when it is processed, then the result is an error and not an empty “ready” result.
3. Given an unsupported role or location, when it is processed, then it is labeled for HR review and is not mapped to invented tasks.
4. Given one intake event, when the same event is processed again, then no duplicate tasks are created.

### 4. Scope Notes

- **In Scope for MVP**: One role and one location; the four Appendix A tasks; Riley’s complete record; varied synthetic inputs; automatic activation of a complete supported record.
- **Deferred**: Additional roles and locations. Production HR intake is out of this release.
